P1
JSON-LD scripts can be broken by client-controlled content
Dismiss
The page escapes normal HTML body/meta fields, but JSON-LD is inserted with raw JSON.stringify output. If client branding or knowledge text contains a closing script tag, it can break out of the application/ld+json script block. The INITIAL_DATA script handles this with a </script replacement; the JSON-LD blocks need the same safe serialization helper.

P2
This is SSR shell injection, not React hydration
Dismiss
The client still uses createRoot into an empty #root and removes the separate #ssr-content node on the next animation frame. That gives crawlers readable HTML, which is good, but React is not hydrating the server-rendered DOM. For 'perfect SSR', use renderToString/renderToPipeableStream for the React app and hydrateRoot on the same root, or accept this as crawler-focused pre-rendering rather than true React SSR.
