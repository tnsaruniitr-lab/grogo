Fix 1 — V1 Must Not Break Live KB

Fix 2 — Use Crawl Job Settings Snapshot
Problem: startCrawlJob() stores settingsSnapshot, but runCrawlPipeline() calls getSettings() again.

Change runCrawlPipeline() to load the job first:

const [job] = await db
  .select({
    extractorVersion: crawlJobsTable.extractorVersion,
    settingsSnapshot: crawlJobsTable.settingsSnapshot,
  })
  .from(crawlJobsTable)
  .where(eq(crawlJobsTable.id, jobId))
  .limit(1);

const settings = job?.settingsSnapshot
  ? { ...DEFAULT_SETTINGS, ...JSON.parse(job.settingsSnapshot) }
  : await getSettings();

const isV2 = job?.extractorVersion === "v2";
Also export DEFAULT_SETTINGS from settings.ts.

Fix 3 — Make Activation Atomic
Problem: activation is sequential, not transactional.

Wrap all activation changes in db.transaction.

Inside the transaction:

Find pending rows for clientId + crawlJobId.
Archive old approved crawl rows only:
approvalStatus = "archived"
where clientId = client.id
and approvalStatus = "approved"
and source != "manual"
and crawlJobId != crawlJobId
Approve new rows:
approvalStatus = "approved"
where clientId = client.id
and crawlJobId = crawlJobId
and approvalStatus = "pending"
Archive old active profiles:
status = "archived"
where clientId = client.id
and status = "active"
Activate the new profile by profileId, or if missing, latest pending profile for that crawl:
status = "active",
activatedAt = new Date()
where clientId = client.id
and crawlJobId = crawlJobId
and status = "pending"
